# Meow Tarot • ทาสแมวพยากรณ์

เว็บดูดวงไพ่ทาโรต์น้องแมว พร้อมระบบสมัครสมาชิก (username + password) และจำกัดสิทธิ์ 1 ครั้ง / ผู้ใช้ / วัน

## โครงสร้างโฟลเดอร์

```
meow-tarot/
├── server.js            ← เซิร์ฟเวอร์ (Express + SQLite)
├── package.json
├── public/
│   ├── index.html       ← หน้าเว็บ
│   ├── tarot_database.json   ← ⚠ ต้องวางไฟล์นี้ไว้ที่นี่
│   └── images/          ← ⚠ ภาพไพ่ 0.png … 77.png วางไว้ที่นี่
└── data/                ← สร้างอัตโนมัติ เก็บฐานข้อมูลผู้ใช้ (meow-tarot.db)
```

## รันบนเครื่อง

```bash
npm install
npm start          # เปิด http://localhost:3000
```

เปิดผ่าน `http://localhost:3000` เท่านั้น (ไม่ใช่เปิดไฟล์ตรง ๆ แบบ file://) เพราะหน้าเว็บต้องคุยกับเซิร์ฟเวอร์

## ระบบบัญชี / ความปลอดภัย

- สมัครเอง: username 3–20 ตัว (ตัวอักษร/ตัวเลข/`_ . -`, ไม่แยกตัวพิมพ์ใหญ่เล็ก), password 8–72 ตัว
- รหัสผ่านถูก hash ด้วย **scrypt** + salt สุ่มรายคน ไม่เก็บรหัสผ่านจริง
- Session เป็น cookie แบบ `HttpOnly` + `SameSite=Lax` (เป็น `Secure` เมื่อใช้ HTTPS/production) อายุ 30 วัน; ในฐานข้อมูลเก็บเฉพาะค่า hash ของ token
- จำกัดการลองล็อกอิน/สมัคร 10 ครั้งต่อ 15 นาทีต่อ IP และป้องกัน CSRF ด้วยการเช็ก Origin
- **สุ่มไพ่และนับสิทธิ์ที่ฝั่งเซิร์ฟเวอร์** ผู้ใช้แก้ค่าในเบราว์เซอร์เพื่อสุ่มซ้ำไม่ได้ และล็อกอินจากเครื่องอื่นก็เห็นผลเดิมของวันนั้น
- วันใหม่นับตามเวลา `Asia/Bangkok` (เปลี่ยนได้ด้วย `APP_TZ`)

> ยังไม่มีระบบ "ลืมรหัสผ่าน" (ไม่ได้เก็บอีเมล) — ถ้าผู้ใช้ลืม ผู้ดูแลต้องลบ/รีเซ็ตบัญชีในฐานข้อมูลเอง

## ตัวแปรสภาพแวดล้อม

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `PORT` | `3000` | พอร์ตของเซิร์ฟเวอร์ |
| `DATA_DIR` | `./data` | โฟลเดอร์เก็บฐานข้อมูล SQLite |
| `NODE_ENV` | – | ตั้งเป็น `production` เมื่อใช้งานจริง (บังคับ cookie `Secure`) |
| `APP_TZ` | `Asia/Bangkok` | เขตเวลาที่ใช้ตัดรอบวัน |

## การ deploy ให้คนอื่นใช้

ต้องใช้โฮสต์ที่รัน **Node.js 18+** ได้ และมี **ดิสก์ถาวร (persistent disk)** สำหรับ `DATA_DIR` เช่น Render, Railway, Fly.io หรือ VPS ทั่วไป

1. อัปโหลดโปรเจกต์ (อย่าอัปโหลด `node_modules/` และ `data/`)
2. Build command: `npm install` — Start command: `npm start`
3. ตั้ง `NODE_ENV=production`
4. ผูก persistent disk แล้วตั้ง `DATA_DIR` ชี้ไปที่ดิสก์นั้น (เช่น `/var/data`) — **ถ้าไม่ทำ ข้อมูลผู้ใช้จะหายทุกครั้งที่ deploy/restart**
5. ใช้ HTTPS (โฮสต์ส่วนใหญ่ให้อัตโนมัติ) — เซิร์ฟเวอร์ตั้ง `trust proxy` ไว้แล้วสำหรับการอยู่หลัง reverse proxy

หมายเหตุ: โฮสต์แบบ static อย่าง GitHub Pages / Netlify static / Firebase Hosting ใช้ไม่ได้ เพราะต้องมีเซิร์ฟเวอร์ให้เก็บบัญชีผู้ใช้
